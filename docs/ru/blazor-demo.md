# Blazor-демо

[English](../en/blazor-demo.md)

Приложение демонстрирует формы Sitko.Core с FluentValidation, навигацию и загрузку
файлов. Оно использует серверную интерактивность и WebAssembly через `InteractiveAuto`.
Данные формы существуют только на открытой странице; файлы сохраняются локально.

## Запуск

Нужны .NET SDK, совместимый с `global.json` в корне репозитория, браузер с поддержкой
WebAssembly и доверенный локальный сертификат ASP.NET Core. Docker, PostgreSQL
и другие внешние сервисы не требуются.

Из корня репозитория выполните:

```bash
dotnet dev-certs https --trust
dotnet run --project apps/Blazor/Sitko.Core.Apps.Blazor --launch-profile https
```

Откройте [https://localhost:7163](https://localhost:7163). Главная страница ведёт
к форме, загрузке файлов и примеру параметра URL. При первом открытии `InteractiveAuto`
использует сервер; WebAssembly загружается в фоне и используется при последующих открытиях.

Приложение предназначено для локального запуска с демонстрационными данными.
Не загружайте конфиденциальные файлы: ссылки на загруженное содержимое не требуют входа.

## Форма и валидация

1. Откройте `/Form` и отправьте форму с пустым именем: должна появиться ошибка обязательного поля.
2. Введите имя `Анна` и сообщение `Пример`, затем отправьте форму. Приложение показывает принятые значения.
3. Измените значения и нажмите сброс. Поля возвращаются к начальному состоянию.

Отправка показывает работу формы и валидации; постоянного хранения формы нет.
Сценарий использует `BaseMudForm<TEntity>` и модель из проекта `Sitko.Core.Apps.Blazor.Data`.

## Файлы

На `/Files` доступны одиночная и множественная загрузка, а также просмотр изображения.
Подготовьте небольшой текстовый файл, несколько файлов и изображение PNG/JPEG.
Лимит одного файла — 2 МиБ, множественного выбора — пять файлов.

После загрузки откройте ссылку и сравните содержимое с исходным файлом. Для изображения
проверьте отображение. При выборе файла больше 2 МиБ должна появиться ошибка размера.

Сервер использует `FileSystemStorage` и `FileSystemStorageMetadata`; браузерная загрузка
WebAssembly обращается к существующему `UploadController` через `Storage.Remote`.
`Repository.Remote` в демонстрации не используется.

Файлы и метаданные находятся в
`apps/Blazor/Sitko.Core.Apps.Blazor/wwwroot/static/demo/`.
Остановите приложение и удалите этот каталог через файловый менеджер для очистки демо.
Файлы вне этого каталога для очистки удалять не требуется.

## Параметр URL

Откройте `/QueryString?test=11111111-1111-1111-1111-111111111111`: страница показывает
указанный GUID. Перейдите по ссылке смены значения, вернитесь назад и обновите страницу.
В каждом случае отображаемое значение должно соответствовать текущему URL.

## Проверка воспроизводимости

Повторите форму, навигацию и загрузку при первом открытии в новом профиле браузера,
затем после загрузки WebAssembly и повторного открытия приложения. Проверьте консоль браузера и журнал сервера на непредвиденные ошибки.
Отклонение слишком большого файла сопровождается сообщением об ошибке размера. Обе проверки нужны:
успешная сборка не подтверждает работу интерактивного интерфейса и передачи файлов.
