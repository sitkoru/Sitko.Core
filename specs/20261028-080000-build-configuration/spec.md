# Общая конфигурация сборки Sitko.Core

**Создано**: 2026-10-28
**Статус**: реализовано
**Основа требований**: общие настройки всех проектов, включая perf; централизация R13 и согласованный переход R04 только на .NET 10; удаление фронтенд-ресурса AntDesign в R15.

## Пользовательские сценарии и проверка

### US1 — Сопровождать общие настройки (P1)

Разработчик меняет общую настройку или версию в одном месте, сохраняя различия
между публикуемыми библиотеками, тестами, примерами и измерениями производительности.

**Независимая проверка**: вычислить настройки каждого проекта, собрать решение и
проверить состав публикуемых пакетов.

1. Общие настройки платформы, языка, nullable, implicit usings и предупреждений
   применяются ко всем проектам, включая измерения производительности в `perf`.
2. Тестовые ссылки, SourceLink и упаковка применяются только в своих областях.
3. Метаданные пакетных ссылок и относительные пути ресурсов сохраняются.

### US2 — Использовать пакеты на .NET 10 (P1)

Разработчик приложения получает пакеты для единственной поддерживаемой платформы
.NET 10 и совместимый стабильный набор зависимостей Microsoft.

**Независимая проверка**: восстановить зависимости приложения из локальных пакетов,
собрать и запустить его на .NET 10; приложение .NET 8 не получает совместимый пакет.

1. Все библиотеки, тесты и примеры собираются для `net10.0` без обязательного SDK 11.
2. Пакеты содержат только сборки `net10.0` и соответствующие группы зависимостей.
3. API массового обновления репозитория сохраняет вариант .NET 10:
   `Action<UpdateSettersBuilder<TEntity>>` с константой либо выражением значения.

### US3 — Собирать AntDesign без npm (P1)

Разработчик собирает и упаковывает `Sitko.Core.Blazor.AntDesign` обычным .NET SDK,
без установки Node.js и запуска отдельной сборки ресурсов. Компоненты используют
оформление AntDesign; дополнительный ресурс `fileupload.js` не поставляется.

**Независимая проверка**: из чистого дерева собрать и упаковать модуль, проверить
отсутствие `fileupload.js` в NuGet и неизменность исходников компонентов и версии AntDesign.

1. В модуле нет каталога `Web`, npm-зависимостей и заменяющего сборщика.
2. `Main` и `Release` не готовят Node.js и не выполняют npm ради AntDesign.
3. Публичный API компонентов и `AntDesign 0.20.4` сохраняются.

### Пограничные случаи

- Вложенный файл настроек явно подключает общий файл, без дублирования объявлений.
- Семейства пакетов Microsoft могут иметь разные актуальные номера версий.
- Стабильный пакет несовместимой платформы не выбирается только ради новизны.
- Примеры, Pdf и Blazor сохраняют действующие способы работы.

## Требования

- **FR-001**: Общие настройки сборки и таблица версий находятся в корне репозитория.
- **FR-002**: Все проекты, включая `apps` и `perf`, получают общие настройки
  C# 14, nullable, implicit usings и предупреждений без условий по каталогам.
  Упаковка, ресурсы и тестовый раннер сохраняют локальную область действия.
- **FR-003**: Общие версии не добавляют пакетных ссылок и сохраняют их метаданные.
- **FR-006**: Единственный TFM сохраняемых проектов и NuGet-пакетов — `net10.0`.
  Поддержка .NET 8 исключена, поддержка .NET 11 не входит в поставку.
- **FR-007**: Сборка использует стабильный SDK .NET 10 без выбора предварительных SDK.
- **FR-008**: Все используемые прямые пакеты Microsoft обновлены до актуальных
  совместимых стабильных версий на момент реализации; номера разных семейств
  выбираются независимо. Npgsql, Razor/Blazor, gRPC, валидация, логирование и OpenTelemetry также
  обновляются до последних совместимых стабильных версий по уточнению пользователя.
  Массовое обновление остальных пакетов не входит в задачу.
- **FR-009**: Удаление ветвей старых платформ сохраняет публичный API и поведение
  прежнего варианта `net10.0`, включая массовое обновление репозитория.
- **FR-010**: CI проверяет единственный TFM .NET 10, сохраняя существующие сценарии,
  изоляцию, отчёты и запрет публикации из `v13`.
- **FR-011**: Инструкции перехода и настройки сборки доступны на русском и английском,
  описывают минимум .NET 10 и необходимые действия потребителя.

- **FR-012**: Модуль AntDesign не содержит отдельной фронтенд-сборки, её исходников,
  npm-манифестов и lockfile. Ресурс `_content/Sitko.Core.Blazor.AntDesign/fileupload.js`
  и его дополнительные стили не входят в пакет v13; замена ресурса не создаётся.
- **FR-013**: `Main` и `Release` не устанавливают Node.js и не запускают npm для
  AntDesign. Существующие .NET-проверки, упаковка и условия публикации сохраняются.
- **FR-014**: Удаление ресурса не меняет компоненты, их API и версию `AntDesign 0.20.4`.
  Потребитель, явно подключавший `fileupload.js`, удаляет подключение; если его
  дополнительные стили нужны приложению, оно сопровождает их самостоятельно.

- **FR-015**: Единственное решение репозитория — `Sitko.Core.slnx`. Переход
  сохраняет состав проектов, папки и вложенность, конфигурации Debug/Release
  для Any CPU/x64/x86 и соответствия проектным платформам. Общие настройки
  `Sitko.Core.sln.DotSettings` сохраняются. SDK, зависимости и код модулей
  при замене формата не меняются.

Требования FR-004/FR-005 о сохранении версий и платформ при централизации R13
заменены требованиями FR-006–FR-010 о действующей платформе и зависимостях.

## Критерии приёмки

- **SC-001**: Все сохраняемые проекты вычисляют только `net10.0`;
  EF Design использует единую централизованную версию.
- **SC-002**: Решение собирается и упаковывается без публикации; состав пакетов
  сохраняется, кроме исключения сборок .NET 8 и ресурса AntDesign `fileupload.js`;
  новых диагностик в изменённом коде нет.
- **SC-003**: Существующие проверки подтверждают работу приложения, репозитория,
  тестового запуска, Pdf, Blazor и интеграций на .NET 10.
- **SC-004**: Приложение .NET 10 восстанавливает локальные пакеты и выполняет вызов
  публичного API; приложение .NET 8 получает ошибку несовместимости NuGet.

- **SC-005**: Чистая сборка и упаковка AntDesign на .NET 10 проходят без npm;
  пакет содержит сборку `net10.0` и зависимость `AntDesign 0.20.4`, но не `fileupload.js`.
- **SC-006**: В обоих workflow нет шагов npm/Node.js для AntDesign; файлы компонентов,
  их проекты и таблица версий не изменены в R15.

- **SC-007**: `perf` получает общие настройки без собственного Directory.Build.props
  и собирается без новых диагностик; у остальных проектов эффективные значения
  и зависимости не меняются при удалении условий корневого props.

- **SC-008**: Состав и конфигурации SLNX совпадают с исходным решением;
  LSP загружает новое решение, сборка и упаковка проходят; CodeQL
  поддерживаемой версии анализирует результат. Второго SLN в репозитории нет.

## Предпосылки и границы

R03, Pdf, обновлённое Blazor-демо и R13 влиты. Новые gRPC/SD, OIDC, общая
переработка CI, массовый аудит сторонних пакетов, публикация и production — вне R04.

Исключения, явно выбранные пользователем: AntDesign оставить `0.20.4` без изменения
кода компонентов; обновление Duende выполнить в R06. Для OpenTelemetry.Instrumentation.GrpcNetClient
стабильного выпуска нет, сохраняется существующая `1.15.1-beta.1`.
