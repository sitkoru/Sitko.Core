# Спецификация: единая конфигурация экспорта OTLP

**Ветка**: `infra/otel/unified-settings-v13`
**Создана**: 2026-10-30
**Статус**: Реализация
**Основание**: согласованный контракт OTEL для v13; [общий план](../../ROADMAP.md).

## Пользовательские сценарии и проверка

### US1 — Авторизация из конфигурации приложения (P1)

Сопровождающий задаёт адрес, протокол и заголовки в существующем разделе
`OpenTelemetry`, используя обычную конфигурацию .NET, включая Vault и
`OpenTelemetry__...`. После перезапуска все включённые сигналы поступают в приёмник.

**Независимая проверка**: реальное приложение Sitko.Core отправляет лог, метрику
и трассу в локальный приёмник, который принимает данные только с правильной
авторизацией. Секреты приёмника — исключительно тестовые литералы.

1. При заданных `Headers` без `OTEL_EXPORTER_OTLP_*` приёмник принимает все три сигнала.
2. Без заголовков приёмник отклоняет запросы; успешный запуск не означает доставку.

### US2 — Переопределение через стандартное окружение (P1)

Сопровождающий сохраняет доставку настроек через поддерживаемые стандартные
`OTEL_EXPORTER_OTLP_*`; раздел приложения служит значениями по умолчанию.

1. Общие `ENDPOINT`, `PROTOCOL`, `HEADERS` переопределяют соответствующие значения
   раздела одинаково у логов, метрик и трассировки.
2. Заголовки из выбранного источника заменяют весь набор, чтобы реквизиты
   из разных источников не отправлялись вместе.
3. Пустые строки окружения трактуются как отсутствие значения.
4. Неподдерживаемые текущим API суффиксы не получают искусственной поддержки.

### US3 — Безопасная проверка и отключение (P1)

1. Отсутствующий адрес в разделе допустим, если поддерживаемый env задаёт корректный адрес.
2. Неверные конечные параметры отклоняются без вывода значений заголовков.
3. Окружение не включает выключенный модуль, экспорт или отдельный сигнал.
4. Программные настройки модуля применяются до разрешения стандартного окружения;
   `ConfigureOpenTelemetry` сохраняет возможность дополнять SDK; его прежний
   порядок вызова после настройки логирования не меняется. Изменять через него
   общие настройки подключения после настройки логирования не следует.

### Пограничные случаи

Пустой адрес; относительный URI; неподдерживаемый протокол; неверный формат
заголовков; отсутствие авторизации; конфликт источников; выключенные сигналы;
поддерживаемые настройки SDK метрик; зарезервированные signal-specific env.

## Требования

[Модель параметров](data-model.md) уточняет форму публичных настроек.

- **FR-001**: Сохранить `EnableOtlpExport`, `Endpoint`, `OtlpExportProtocol`,
  `EnableLogs`, `EnableMetrics`, `EnableTracing`; добавить `Headers` как словарь.
- **FR-002**: Общие поддерживаемые env `OTEL_EXPORTER_OTLP_ENDPOINT`,
  `OTEL_EXPORTER_OTLP_PROTOCOL`, `OTEL_EXPORTER_OTLP_HEADERS` имеют одинаковый
  приоритет над разделом для всех трёх сигналов.
- **FR-003**: Заголовки выбираются целиком из одного источника; пустое env не
  стирает конфигурацию. Ошибки не раскрывают имена или значения заголовков.
- **FR-009**: `Endpoint` при `HttpProtobuf` — общий базовый URL; к нему добавляются
  `v1/logs`, `v1/metrics`, `v1/traces`. При `Grpc` адрес передаётся без этих путей.
  Изменение прежней семантики точного HTTP URI требует миграции конфигурации.
- **FR-004**: Проверять конечные адрес, протокол и заголовки после разрешения
  источников; требовать адрес только для включённого экспорта включённых сигналов.
- **FR-005**: Окружение не изменяет флаги включения модуля и экспорта.
- **FR-006**: Сохранить штатные экспортёры SDK и Serilog sink и прочие их env
  настройки, включая ресурсы и агрегацию метрик. Таблица фактически поддерживаемых
  имён находится в [руководстве](../../docs/ru/observability.md).
- **FR-007**: Сохранить программные callbacks; настройки источников применяются
  после конфигурации модуля, а SDK callbacks продолжают расширять регистрацию.
  Произвольные поздние изменения через SDK API подчиняются порядку SDK;
  принудительный env-приоритет над ними не гарантируется.
- **FR-008**: Соединения перенастраиваются после перезапуска; горячая перенастройка,
  новые режимы, Collector, именованные экспортёры, новые зависимости исключены.

## Критерии успеха

- **SC-001**: Локальный приёмник подтверждает содержимое и авторизацию каждого
  из трёх сигналов при конфигурации без env и при переопределении через env.
- **SC-002**: Конфликт адреса и реквизитов разрешается одинаково у трёх сигналов;
  реквизиты проигравшего источника не поступают в приёмник.
- **SC-003**: Неверная конфигурация отклоняется без раскрытия значений;
  отключённый экспорт не отправляет запросы даже при заданном env.

## Предпосылки и границы

Только Sitko.Core v13 и .NET 10. Инфраструктура, Vault, Helm, production,
потребители, версии пакетов и выпуск не изменяются. Локальная приёмка не доказывает
работоспособность production OpenObserve.
