## Результат и технический контекст

.NET 10, C# 14, ASP.NET Core 10.0.14; Duende AccessTokenManagement 4.3.0.
Сохраняются стандартные OIDC/JWT/cookie-обработчики и публичный IUserTokenProvider.
Переименование включает пакет, типы, регистрации и конфигурацию. Требуется адаптация
IUserTokenStore и менеджера токенов к API Duende 4. Прямой JwtBearer 10.0.14 заменяет
транзитивный JwtBearer 3.0.0 из удаляемого IdentityServer4.AccessTokenValidation.

## Constitution Check

Согласованный контракт FR-001–009 ограничивает изменение одним модулем и его тестами.
Существующий механизм — Auth.IdentityServer на стандартных AddOpenIdConnect/AddJwtBearer,
IUserTokenProvider и двух IUserTokenStore. Полная собственная OIDC-реализация не нужна.
Механическое переименование недостаточно: остаётся устаревшая зависимость IdentityServer4
и отсутствует настройка OpenIdConnectOptions. Миграция Duende требует новых контрактов
токенов; формат Redis сохраняется, чтобы не потерять пользовательские refresh tokens.
Изменять модель ключей, политику допуска или механизм конкурентного обновления не нужно.
Используются штатные возможности Duende. Проверка пропорциональности ponytail пройдена.
До и после проектирования противоречий конституции не обнаружено.

## Проверки и порядок

1. Базовые RedisOptionsTests: 14 passed, 0 failed, 0 skipped.
2. Сохранить диагностики csharp-ls; проверить миграцию пакета и исходные контракты Duende.
3. Последовательно: тест наблюдаемого поведения → минимальная реализация → проверка.
4. Через настоящий ASP.NET pipeline и изолированный OIDC-сервер: challenge/PKCE,
callback/cookie, отклонённый вход, JWT issuer/audience/signature/lifetime,
получение/refresh/revoke токенов. Подменяется только внешний поставщик.
5. Через зарегистрированный IUserTokenStore: существующий формат данных, сохранение,
чтение, удаление и отсутствие идентификатора. Redis/Sentinel/Cluster — только отдельные
стенды задачи; общий localhost не используется.
6. Сборка/упаковка модуля, диагностики изменённых файлов, RU/EN и проверка ссылок.
7. Независимое ревью, исправления, PR в v13; весь CI на неизменном head, затем разрешённое
слияние. Подтверждение SHA и очистка чистого дерева.

Реальный Keycloak и Blazor-интерфейсы потребителей проверяются при их отдельной миграции.
В этой поставке проверяется библиотечная серверная граница и описывается ручная приёмка.
