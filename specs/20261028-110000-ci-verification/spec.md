# Проверки изменений Sitko.Core

**Создана**: 2026-10-28

**Статус**: согласована, реализация проверяется

## Пользовательские сценарии и проверка

### Сценарий 1 — полный результат проверки (P1)

Сопровождающий получает результат всех сохраняемых исполняемых тестовых проектов
на `net10.0`, кроме SMTP-сценария с внешней отправкой.

**Независимая проверка**: сопоставить проекты с `tests/Directory.Build.props` и
командами Main; запустить четыре добавленных набора.

1. При изменении PR Main запускает существующие наборы и конкретные проверки
   App.Web, Grpc.Server, Repository.Grpc и Repository.
2. Если тест завершается ошибкой или не выполняет ни одного сценария, задание
   не становится успешным; созданные отчёты и диагностика доступны как артефакт.

### Сценарий 2 — воспроизводимая подготовка и актуальный PR (P1)

Сопровождающий проверяет актуальную версию PR на известном SDK и готовых сервисах.

**Независимая проверка**: проверить образ, готовность, события и условия отмены.

1. Новый запуск того же PR может отменить устаревший запуск того же workflow.
   Запуски push и выпуска не отменяются этой политикой.
2. Изменения `v13` проходят CodeQL при push и PR; недоступный сервис останавливает
   зависимую проверку с ошибкой.

### Пограничные случаи

Ошибка сборки может не создать TRX: сохраняется доступная диагностика. Если
предыдущий набор в задании упал, последующие шаги сохраняют обычные условия запуска.
Абстрактные Email.Tests/Storage.Tests и пустой Tasks.Kafka.Tests не запускаются
отдельно; Email.Smtp.Tests не отправляет почту из CI.

## Требования

- **FR-001**: Main запускает все сохраняемые исполняемые тестовые проекты на
  `net10.0`, за исключением Email.Smtp.Tests с внешней отправкой.
- **FR-002**: Каждый запуск требует хотя бы один выполненный тест, сохраняет
  отдельный TRX и диагностический журнал; задание пытается загрузить созданные
  файлы и при ошибке. Каталог различает задание, проект и платформу, а для PDF — режим.
- **FR-003**: Ошибка теста или готовности сервиса сохраняет ненулевой результат
  задания. Условия и зависимости release остаются действующими.
- **FR-004**: Все задания Main с SDK используют подтверждённый образ по digest.
  CodeQL проверяет push и PR в `v13` с .NET SDK `10.0.403`.
- **FR-005**: Отмена устаревших запусков ограничивается одним PR и workflow.
  Разные PR, push и выпуск сохраняют независимость.
- **FR-006**: Существующие внешние сервисы проверяются перед использованием;
  изоляция, диагностика и очистка Redis/Valkey сохраняются.

## Критерии успеха

- **SC-001**: Каждый исполняемый проект учтён запуском или явным SMTP-исключением;
  четыре добавленных набора выполняют ненулевое число тестов.
- **SC-002**: Ошибочный тест или недоступный сервис не даёт успешного задания,
  а созданные отчёты не теряются из-за ошибки.
- **SC-003**: Условия публикации, состав обязательных заданий и блоки npm не
  изменены этой возможностью.

## Ограничения

Контракт дополняет [тестовую платформу](../20261028-103000-test-platform/spec.md)
и [конфигурацию сборки](../20261028-080000-build-configuration/spec.md).
Новые тестовые сценарии, .NET 11, новые матрицы, новые стенды, изменение
пакетов/раннера, Blazor pack и публикация пакетов не входят в это изменение.
Ускорение без сопоставимого замера не гарантируется.
