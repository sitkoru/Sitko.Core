# Спецификация: сокращённое Blazor-демо

**Ветка**: `infra/blazor/simplify-demo`  
**Дата**: 2026-10-27  
**Статус**: действующий контракт демонстрации  
**Основание**: сохранить формы, валидацию, навигацию и загрузку файлов без Repository.Remote.

Связанная задача: [R10](../../ROADMAP.md#r10). Удаление библиотек относится к R03.

## Пользовательские сценарии и проверка

### US1 — Форма с валидацией (приоритет P1)

Разработчик открывает демо и пробует форму, не настраивая базу данных.
Проверка выполняется через настоящий интерфейс и действующие компоненты формы/валидации.

1. При отправке пустого обязательного имени показана понятная ошибка; успешный результат не отображается.
2. После ввода имени «Анна» и сообщения «Пример» отправка показывает именно эти принятые значения.
3. Изменение полей и сброс возвращают определённые начальные значения.
4. Интерфейс объясняет, что отправка формы не сохраняет данные между открытиями страницы или запусками.

### US2 — Загрузка файлов (приоритет P1)

Разработчик загружает локальные демонстрационные файлы и видит результат.

1. Текстовый файл меньше 2 МиБ загружается, отображается ссылка; открытое содержимое совпадает с исходным.
2. Можно загрузить несколько файлов и увидеть каждый результат; для изображения доступен просмотр.
3. Файл больше 2 МиБ отклоняется с понятным сообщением, без успешного результата для этого файла.
4. Файлы и метаданные находятся в явно указанном локальном каталоге, инструкции описывают очистку.

### US3 — Навигация (приоритет P2)

Стартовая страница `/` объясняет доступные сценарии и содержит ссылки на форму `/Form`, файлы `/Files` и параметры URL `/QueryString?test=<guid>`.
Параметр URL отображается на странице; переход по ссылке меняет значение, возврат назад и обновление
страницы восстанавливают значение из текущего URL. Отсутствующий параметр имеет понятное начальное значение.

### Пограничные случаи

Пустая форма, отсутствующий параметр URL, несколько файлов и превышение лимита проверяются явно.
Демо использует только локальные демонстрационные данные; файлы пользователя вне каталога демо не изменяются.

## Требования

- **FR-001**: приложение запускается без Repository.Remote, EF/PostgreSQL и обязательных внешних сервисов.
- **FR-002**: форма обеспечивает US1 с действующей валидацией и наблюдаемым результатом отправки и сброса.
- **FR-003**: загрузка обеспечивает US2 с локальным хранением файлов и метаданных.
- **FR-004**: навигация обеспечивает US3 и не содержит ссылок на удалённые страницы.
- **FR-005**: согласованные сценарии работают при серверной интерактивности и после загрузки WebAssembly.
- **FR-006**: инструкции на русском и английском описывают предпосылки, команды, адрес, данные, результат и очистку.
- **FR-007**: библиотеки Repository.Remote и их тесты остаются в своей задаче удаления; gRPC/OIDC/PDF здесь не меняются.

### Данные

Форма содержит обязательное имя и демонстрационное сообщение. Принятые значения существуют только
в текущей демонстрации. Загруженные файлы и их метаданные сохраняются локально до явной очистки.

## Критерии успеха

- **SC-001**: все три сценария воспроизводятся по инструкции без личной конфигурации и внешних сервисов.
- **SC-002**: форма отклоняет пустое имя и показывает точные принятые значения исправленной формы.
- **SC-003**: содержимое скачанного файла совпадает с загруженным; превышение лимита видно пользователю.
- **SC-004**: при переходах, возврате назад и обновлении значение соответствует текущему URL.

## Предпосылки и границы

Сохраняются текущие платформы проектов; переход на .NET 11 относится к R04.
Новые библиотечные механизмы, хранилище форм, авторизация и универсальный запускатель не требуются.
Проверка — согласованная локальная приёмка; новые границы автотестов не определяются.
