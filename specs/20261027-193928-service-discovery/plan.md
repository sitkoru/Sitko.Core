# План: обнаружение gRPC-сервисов

**Ветка**: `infra/service-discovery/microsoft-consul`. **Обновлено**: 2026-10-28. **Контракт**: [spec.md](spec.md).

Архитектура и проверки согласованы. Команда на реализацию получена 2026-10-28; локально подтверждены V01–V16. Все согласованные группы локально пройдены; после удаления старых модулей предстоят итоговая сборка и ревью.

## Краткое решение

SD остаётся отдельной необязательной возможностью. Общий `Sitko.Core.ServiceDiscovery` тонко интегрирует Microsoft SD; новый объединённый `Sitko.Core.ServiceDiscovery.Consul` содержит DNS SRV, нужный HTTP-клиент агента, публикацию контрактов и TTL. Старые отдельные Consul-модули, свой каталог/cache/resolver и `sd:///` удаляются. gRPC не зависит от Consul.

Один `AddGrpcClient<T>` выбирает прямой адрес либо SD по конфигурации; отсутствие требуемого SD и ошибочный URI обнаруживаются при старте. Microsoft HTTP-обработчик выбирает endpoint до отправки RPC; TLS/HTTP/2 передают тело напрямую серверу, соединения переиспользуются. Для SD используется штатный `RoundRobin` Microsoft. Собственный провайдер и кэш последних адресов не вводятся.

Полный protobuf-контракт и окружение определяют DNS-safe имя. Публикуется контракт × экземпляр после bind с фактическим TLS-портом существующего `WebPorts`; несколько контрактов используют один порт. Единственный управляемый цикл владеет регистрацией, heartbeat, повторной регистрацией и удалением только своих ID.

Единая модель общих/индивидуальных параметров и их приоритет, повторные регистрации сервера, токены каждого RPC, reflection и выключение SD описаны в [module-api.md](contracts/module-api.md). Миграция MYCG описывается, его код не меняется.

Проверяется наблюдаемое поведение по [verification.md](contracts/verification.md), без полного нового тестового фреймворка и без теста 256 МиБ. После проектирования нарушений конституции не выявлено; независимое ревью реализации ещё не выполнено.

## Области будущих изменений

- `src/Sitko.Core.Grpc/` — полная protobuf-идентичность.
- `src/Sitko.Core.ServiceDiscovery/` — тонкая интеграция Microsoft SD и объявления.
- `src/Sitko.Core.ServiceDiscovery.Consul/` — объединение прежних Consul-реализаций и нужного HTTP-клиента; удалить заменённые проекты/ссылки, без отдельного `Sitko.Core.Consul`.
- `src/Sitko.Core.App.Web/AppWebConfigurationModule.cs` — связь имени существующего TLS-слушателя с фактическим портом.
- `src/Sitko.Core.Grpc.Client/`, `src/Sitko.Core.Grpc.Server/` — единый API, настройки, валидация и optional SD.
- `tests/Sitko.Core.Grpc.Client.Tests/` — публичные проверки и своя тестовая оснастка; минимальный дочерний host для настоящего аварийного завершения при необходимости.
- `apps/gRPC/`, `docs/`, `.sln` и проектные ссылки — только фактически затронутые потребители/пакеты и миграция.

Не вводятся заранее новые публичные типы для гипотетических провайдеров или универсальная иерархия настроек. Детали внутренних типов закрепляются при реализации без изменения согласованного контракта.

## Этапы и исполнение

Прямое ограничение пользователя от 2026-10-28: перед слиянием PR дождаться его код-ревью. Подготовка, проверки и создание PR разрешены; зелёный CI и прежняя общая стратегия координатора сами по себе не разрешают слияние R07.

Подготовка → анализ согласованности → отдельная команда на реализацию → вертикальные циклы TDD по [tasks.md](tasks.md) → диагностики/сборка `net10.0`/узкие проверки → независимое ревью и `speckit-converge`. Завершены циклы V01–V16; выполненные проверки фиксируются по фактическим результатам. После их завершения обычный PR направляется в `v13`; слияние, публикация, теги и развёртывание не входят в этот план подготовки.

Каждый цикл реализует один наблюдаемый сценарий; не пишется весь набор до появления реального API. Связанные общие регистрации меняются последовательно. Параллельные писатели общих файлов не планируются. Проверки V01–V16 описаны один раз в контракте; задачи содержат ссылки и ID. Полный результат включает все требования, первый успешный RPC — только промежуточный шаг.

Рабочие материалы остаются до завершения реализации и ревью. Очистка по `specs/README.md` не выполняется на стадии подготовки.
