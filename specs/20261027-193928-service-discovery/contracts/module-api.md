# Публичная регистрация и настройка

Контракт описывает выбор адреса, общий выключатель SD, валидацию запуска, приоритет настроек и fluent-регистрацию сервера. Проверки определены в [verification.md](verification.md); результаты конкретной ревизии сохраняются в PR. Справочник реализованных параметров находится в [документации](../../../docs/ru/grpc-service-discovery.md).

## Модули и регистрация

SD остаётся отдельной необязательной возможностью, не частью базового App. `Sitko.Core.ServiceDiscovery` — тонкая интеграция Microsoft SD, общие объявления и включение. В `Sitko.Core.ServiceDiscovery.Consul` объединяются прежние `Resolver.Consul`, `Server.Consul` и необходимый Consul HTTP-клиент. Отдельный `Sitko.Core.Consul`, собственные resolver/cache, подписки и `sd:///` удаляются. Новый каталог подключений и абстракции гипотетических провайдеров не вводятся.

`AddConsulServiceDiscovery(...)` подключает общий SD и провайдер один раз. Клиентский host не требует `IServer`; публикация появляется только для объявленных серверных контрактов. gRPC-модули знают общий SD, без зависимости от Consul.

`AddGrpcClient<TClient>()` — единая регистрация для прямого адреса и SD:

| Конфигурация | Результат |
| --- | --- |
| Корректный `Address` | Прямой вызов; SD не требуется |
| Нет `Address`, SD включён и провайдер подключён | Логическое HTTPS-имя, штатный Microsoft DNS SRV |
| Нет `Address`, нет SD/провайдера либо SD выключен | Понятная ошибка при старте с именем контракта |
| Некорректный URI | Ошибка конфигурации при старте, без перехода на SD |
| Прямой адрес недоступен во время работы | Ошибка/отмена RPC, без перехода на SD |

Смена способа адресации требует конфигурации и перезапуска, без перекомпиляции. Прежние `External`-модули не сохраняются как параллельный способ регистрации. gRPC-Web остаётся поддерживаемым транспортным расширением.

Сервер регистрируется цепочкой `AddGrpcServer(globalOptions).RegisterService<TService>(specificOptions)`. Повтор `AddGrpcServer` дополняет один модуль приложения. Повтор того же типа не добавляет маршрутов и SD-записей. Общие обработчики настроек накапливаются; все сервисы получают итоговые общие настройки, включая добавленные после их регистрации. Разные типы реализации одного protobuf-контракта — ошибка конфигурации. Состояние принадлежит builder приложения, без статического флага процесса.

Клиентский модуль — `GrpcClientModule<TClient>`, серверный — `GrpcServerModule`. У них нет отдельного слоя наследования для прямой адресации и SD. `IGrpcClientModule<TClient>`, `IGrpcServerModule` и `IServiceDiscoveryModule` сохраняют публичные точки объявления зависимостей модулей. Настройка потребителей выполняется через регистрацию и параметры; `GrpcClientModule<TClient, TOptions>` и `BaseGrpcServerModule<TOptions>` не предоставляются.

## Конфигурация и приоритет

Целевая структура: `Grpc:Client:Default`, `Grpc:Client:Contracts:<полное protobuf-имя>`, аналогичные `Grpc:Server:Default`/`Contracts`, `Grpc:Server:EnableReflection` (по умолчанию `false`). Размеры сообщений задаются в байтах. `Address` относится к настройкам клиента. Отсутствующие значения индивидуального контракта не заменяют весь общий объект.

Порядок для клиента и сервера: значения SDK → общая конфигурация `Default` → общий обработчик настроек → конфигурация `Contracts` → индивидуальный обработчик настроек. На каждом уровне применяются только явно заданные значения. Несколько обработчиков настроек одного уровня выполняются по порядку, последнее явное присваивание побеждает. Общая политика охватывает клиентов из зависимых модулей независимо от порядка регистрации.

Размеры, тайм-ауты, deadline, параметры соединения, флаги и параметры поддерживаемой ограниченной политики повторов доступны через конфигурацию. Типы зависимостей и исполняемые стратегии остаются в коде и DI; универсальный сериализатор произвольных SDK-объектов не нужен. Повторы RPC отделены от повторов DNS и регистрации; прозрачный повтор любых операций не обещается.

Все параметры подключения Consul принадлежат провайдеру SD; прежняя отдельная секция модуля `Consul` не сохраняется вторым источником. Целевая секция — `ServiceDiscovery:Consul`. Параметры: HTTP endpoint агента; DNS servers/port, timeout попытки, max attempts, refresh, min/max retry и backoff; TTL, heartbeat, задержка удаления, timeout и интервал повторной регистрации. Имена полей закреплены в `ConsulServiceDiscoveryOptions` и справочнике параметров в документации. Применения после перезапуска достаточно.

Инварианты: интервалы и число попыток положительны; heartbeat меньше TTL; максимальная задержка повтора не меньше начальной; адрес объявления не wildcard; фактический порт положителен. Диагностика называет контракт и ошибочные поля, но точный текст исключения не является контрактом.

Один `ServiceDiscovery.Enabled` отключает провайдер, поиск, публикацию и TTL. Прямые клиенты и сервер продолжают работать. SD не нужен приложению, которому обнаружение не требуется. Старую регистрацию всех приложений и проверку Consul leader не восстанавливаем; в исследованном v12 безусловной регистрации всех приложений уже нет. Контрактный TTL нужен.

Адрес/порт слушателя остаётся в `Application:Web:Ports`. Для Kubernetes доступный Pod IP передаётся через `ExternalAddress` выбранного gRPC-порта. Публикуется фактический TLS HTTP/2-порт после bind, включая `Port=0`; общий универсальный реестр портов не добавляется.

## TLS, расширения и MYCG.Core

Сохраняются TLS, `AddCallCredentials`, поставщики metadata, интерцепторы, настройки канала/HTTP-обработчика и явная политика сертификатов. Поставщик токена вызывается для каждого RPC; клиент может переопределить общий поставщик. Передача credentials без TLS автоматически не включается. Серверная входящая JWT-авторизация остаётся отдельной задачей.

План перехода MYCG.Core: один `AddMycgGrpc()` задаёт общие токены, логи и сертификаты; сам не добавляет сервер и Consul. Обычные клиенты и серверы регистрируются Sitko.Core API. Убираются обёртки каждого клиента/сервера, `GrpcClientsAddresses`, статические флаги и неявное подключение SD из `AddMinimal`/`AddWeb`. Доменные protobuf-сообщения, преобразования типов и пользовательский контекст MYCG остаются. Код MYCG.Core этим поручением не меняется; тестовый поставщик токена проверяет механизм Sitko.Core, не MYCG/IdP.

## Несовместимость и действия потребителя

Потребители согласованно меняют серверы, клиентов, пакеты и конфигурацию. Удаляются `IServiceDiscoveryResolver`, `BaseServiceDiscoveryResolver`, `ServiceDiscoveryResolverFactory`, старые registrar/resolver-регистрации и `sd:///`. Прежние записи приложения/порта и Base64-метаданные не читаются; двойной публикации и совместимости нет. Ключи настроек и перенесённые прямые адреса используют полные protobuf-имена в `Contracts`.

При SD адрес выбирает штатный `RoundRobin` Microsoft, встроенная балансировка grpc-dotnet в этом пути отключается. Прежний `LoadBalancingPolicy` нельзя перенести без изменения смысла; эквивалентность прежних `None`/`PickFirst` не обещается. Собственный балансировщик не входит в переход.

Проверки этого контракта и связь с требованиями — [verification.md](verification.md).
