# Контракт регистрации Consul

Каждая запись представляет один полный protobuf-контракт одного экземпляра приложения. `Name` — общее DNS-имя пары окружение/контракт; `ID` различает экземпляры и их контракты; `Address` и `Port` доступны вызывающему клиенту.

DNS-метка имеет формат `grpc-<окружение>-<короткий-контракт>-<хеш>`. Берётся часть полного protobuf-имени после последней точки, удаляется только завершающий `Service` с точным регистром. Окружение и короткое имя преобразуются стандартной `JsonNamingPolicy.KebabCaseLower`; последовательности символов вне `a-z0-9` заменяются одним дефисом, краевые дефисы удаляются. Пустые части не добавляют завершающий дефис.

Хеш всегда присутствует: первые 12 символов SHA-256 в нижнем шестнадцатеричном регистре от UTF-8 строки `<длина окружения>:<окружение><полное имя контракта>`. Длина окружения берётся как `string.Length`; в хеше сохраняются исходные регистр, символы и полное имя. Он различает совпадающие короткие имена и результаты нормализации с вероятностной защитой 48 бит, а не гарантирует математическую уникальность.

Читаемая часть `grpc-<окружение>-<короткий-контракт>` ограничивается первыми 50 символами без завершающего дефиса, затем добавляется `-<хеш>`. Общая длина — не более 63 символов. ID экземпляра: `<IApplicationContext.Id:N>-<DNS-метка>`.

Пример: `production` и `MYCG.Auth.Grpc.UsersService` дают `grpc-production-users-2dddfe5cbf3f`. Старые имена с 58 hex не обнаруживаются этой схемой; клиент и сервер должны использовать одинаковую версию генератора. Двойная регистрация не выполняется.

В метаданных сохраняются исходное полное имя контракта, окружение и сведения приложения для диагностики. Они не являются собственным протоколом чтения каталога: клиент получает адреса через стандартный SRV-запрос `<Name>.service.consul`.

Регистрация включает TTL check. Первый heartbeat следует сразу за успешным созданием. В дальнейшем регистрация и heartbeat обращаются к тому же настроенному агенту. Потеря регистрации приводит к повторной регистрации; недоступность Consul ограничена тайм-аутом запроса и интервалом следующей попытки.

После штатного завершения удаляются только ID данного экземпляра. После аварийного завершения истёкший TTL исключает экземпляр из здоровых результатов; физическое удаление каталожной записи может произойти позже. Время исключения из здоровых результатов и время физического удаления — разные свойства.

Настройка Consul DNS должна исключать critical экземпляры. Дополнительная настройка only-passing относится к общей инфраструктуре, а не к ручной таблице контрактов. Клиент не интерпретирует статусы здоровья сам.

Рекомендуется обращение непосредственно к доступному Consul DNS с явно настроенными серверами. Системные DNS-настройки macOS/Windows/Linux не изменяются тестами или библиотекой.


Владелец публикации, HTTP-клиента агента и DNS-настроек — объединённый `Sitko.Core.ServiceDiscovery.Consul`; gRPC от него не зависит. Отключение единственным `ServiceDiscovery.Enabled` прекращает весь SD, сохраняя серверные RPC и прямые клиенты. Публикуются только объявленные контракты, без регистрации каждого App и без Consul leader healthcheck. До готовности слушателя регистрации отсутствуют. При остановке цикл подтверждения прекращается до удаления собственных записей. Для именованного порта используется конкретный слушатель Kestrel; после bind проверяются фактический положительный порт, HTTP/2, TLS и доступный адрес объявления. Wildcard-адрес не публикуется.

При отсутствующей или пустой `Application:Web:Ports` адрес и фактический порт берутся после запуска Kestrel из `IServerAddressesFeature`. Для фильтрации по `ServiceDiscoveryPortNames` используется имя `https`; HTTP-адреса не публикуются. Подходящий HTTPS-адрес должен быть единственным, иначе запуск завершается ошибкой с именем контракта. Wildcard преобразуется в локальный loopback. Этот путь предназначен для отдельных процессов на одном хосте; HTTPS-слушатель должен поддерживать HTTP/2, его протоколы настраиваются средствами Kestrel.
