# Предлагаемая проверка поведения

Проверки ещё не выполнены. Перед написанием тестов пользователь подтверждает перечисленные публичные границы. После реализации здесь появятся фактически проверенные команды по `run-tests`; вымышленные параметры runner не используются.

## Изоляция

В существующем `tests/Sitko.Core.Grpc.Client.Tests` запускается только принадлежащий fixture Consul-контейнер Testcontainers, с уникальным именем и случайными loopback-портами. Все тестовые приложения получают его HTTP/DNS-адреса явно. Нельзя использовать shared `localhost:8500`, контейнеры другой сессии, kind, Vault или production. Удаляется только контейнер этой fixture.

Бизнес-клиенты и серверы остаются настоящими хостовыми Kestrel/Host-процессами либо экземплярами хостов тестового процесса; сетевые HTTP/2 и TLS-соединения реальные. Отдельный запуск из Rider не нужен. Временные поколения сервера получают порт через `0`.

## Граница 1: публичная регистрация клиента и сервера

**Данные**: два protobuf-пакета с одинаковым коротким service-именем; дополнительный контракт на том же TLS-порту; разные окружения; два одновременно работающих экземпляра одного приложения/окружения/контракта. Один клиент регистрирует модуль зависимого тестового пакета/проекта, который вызывает публичный `AddGrpcClient`.

**Реальный код**: модуль Sitko.Core, извлечение полного контракта, регистрация Consul, официальный DNS SRV Microsoft и gRPC HTTP/2. Реальные контрактные сообщения генерируются имеющимся `.proto`-инструментом.

**Замены**: только поставщик тестового токена возвращает заранее известное значение. Реальный сервер проверяет `Authorization` и отклоняет отсутствие/неверный токен. Внешняя система выдачи токенов не запускается.

**Ожидаемый результат**: ответы содержат заранее заданные разные идентификаторы контрактов/окружений; сервер получает ровно ожидаемый токен по TLS; дополнительный обычный HTTP-порт не выбирается. Для двух одновременных экземпляров RPC возвращают оба заранее заданных идентификатора; после остановки одного последующие стабильные вызовы возвращают оставшийся экземпляр. Источник ожиданий — объявленные тестовые protobuf-пакеты и литералы ответа, а не повторение алгоритма DNS-имени в проверке.

**Доказывает**: правильную маршрутизацию, автоматическую регистрацию и сохранение передачи токенов. **Не доказывает**: production PKI, внешний identity provider и реальную публикацию NuGet.

## Граница 2: жизненный цикл прежнего клиента

**Данные**: один сохранённый DI provider и экземпляр каждого клиента; три последовательных поколения сервера, каждый с новым фактическим TLS-портом. Одно поколение останавливается штатно, другое завершается аварийно либо прекращает heartbeat с подтверждённо отсутствующим сервером.

**Реальный код**: регистрация, heartbeat, TTL, снятие регистрации, обновление DNS и HTTP-пул. Между поколениями тест повторяет только безопасный читающий RPC, ограничивая время каждого вызова и общий срок 60 секундами на восстановление.

**Ожидаемый результат**: прежние клиенты получают поколение 1, затем 2 и 3. При отсутствии всех серверов вызов завершается ошибкой/отменой; после TTL мёртвый экземпляр исключён. Счётчик создания канала не растёт на каждый RPC; это дополнительная диагностика, основной результат — реальные ответы правильного поколения.

**Доказывает**: смену порта и восстановление следующих вызовов. **Не доказывает**: перенос выполняющегося потока, прозрачные повторы операций или производственный RTO.

## Граница 3: конфигурация, отказ и восстановление Consul

**Данные**: ускоренные интервалы теста (обновление DNS 1 секунда, TTL 3 секунды, heartbeat меньше TTL); варианты DNS timeout/attempts, некорректные интервалы; отключение и возврат только собственного Consul-контейнера.

**Реальный код**: привязка конфигурации модуля, штатный DNS resolver, ограниченные попытки регистрации и поддержка CancellationToken. Изменения настроек применяются новыми хостами без новой сборки.

**Ожидаемый результат**: недопустимая конфигурация выдаёт ошибку; RPC при отказе завершается в заданном ограничении; после возврата Consul и повторной регистрации следующие вызовы работают. Если приложение запущено при недоступном Consul, регистрация повторяется после готовности слушателя и восстановления агента. Успешные RPC во всё время отказа не требуются.

**Доказывает**: настройку, ограничение ожидания и последующее восстановление. **Не доказывает**: HA Consul, потерю зоны и настройки других DNS-резолверов ОС.

## Граница 4: большой ответ и прямое сравнение

**Данные**: детерминированный ответ 256 МиБ с заранее заданным содержимым; лимиты сообщений явно разрешают этот размер.

**Реальный код**: один серверный метод и реальная сериализация/HTTP/2/TLS; прямой клиент с известным фактическим адресом сравнивается с клиентом через обнаружение. Дополнительного прокси нет.

**Ожидаемый результат**: длина и содержимое совпадают с исходными данными, фиксируются время и выделения памяти последовательных обращений. Источник ожидаемого результата — исходный фиксированный массив, а не преобразование полученного ответа.

**Доказывает**: прохождение большого ответа и расходы конкретного локального опыта. **Не доказывает**: SLA production или универсальную пропускную способность. Жёсткий неподтверждённый процент допустимой регрессии не вводится.
