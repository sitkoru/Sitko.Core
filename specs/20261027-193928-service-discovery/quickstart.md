# Подготовка проверки SD/gRPC

Архитектура и V01–V16 согласованы. Реализация и выполнение проверок не начаты. Данные, ожидания, ограничения и матрица требований/задач находятся в одном месте: [contracts/verification.md](contracts/verification.md).

## Предварительные условия

Рабочая ветка `infra/service-discovery/microsoft-consul` основана на `v13`. Целевая платформа только `net10.0`, SDK `10.0.403`. Используются уже принятые xUnit `4.0.2`, MTP `2.5.1`, AwesomeAssertions `9.6.0`; отдельная миграция runner не нужна. Централизованные версии пакетов находятся в корневом `Directory.Packages.props`.

Для инфраструктурных сценариев нужна только собственная тестовая оснастка Consul на Testcontainers. Она публикует HTTP/DNS на случайных loopback-портах; UDP/TCP DNS учитываются отдельно. Клиенты и серверы — настоящие App/Kestrel/TLS на случайных портах. Удалять можно только ресурсы, созданные этой тестовой оснасткой. Shared `localhost:8500`, чужие стенды, kind, Vault и production запрещены.

## Порядок после отдельной команды на реализацию

1. Сохранить исходные диагностики затрагиваемых C#-файлов и проверить действующий runner по `run-tests` и актуальной документации репозитория.
2. Выполнять вертикальные циклы TDD по [tasks.md](tasks.md): один согласованный сценарий → наблюдаемое падение → минимальная реализация → успешная проверка. Не писать заранее весь воображаемый набор.
3. Последовательно проверить обычный TLS RPC, конфигурацию и серверный API, затем жизненный цикл/отказы с собственным Consul. V07/V08/V09/V11/V15 работают без Consul.
4. Собрать затронутые проекты для `net10.0`, выполнить узкий согласованный набор, повторить диагностики. Сохранить точные команды и результаты при фактическом выполнении; не подставлять старые `--filter` в MTP-команду без проверки.
5. Выполнить независимое ревью и `speckit-converge`. Результаты одной ОС, локального запуска и CI описывать раздельно.

Предел 60 секунд относится только к отмеченным сценариям с ускоренными тестовыми интервалами. У каждого RPC свой конечный deadline; он не подменяет проверку DNS timeout в V16. Нет проверки ответа 256 МиБ, сравнения времени/памяти, production RTO, HA Consul либо внешнего IdP.

Команды сборки/тестов пока не приводятся: исполняемые проверки ещё не написаны. Наличие этого руководства не подтверждает их выполнение.
