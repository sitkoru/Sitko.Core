## Зависимости и порядок

T001 → T002 → T003 → T004 → US1 → US2 → US3 → завершение. T005–T014 выполняются вертикальными проверяемыми шагами; до появления seam из предыдущего шага зависимый тест не выдумывается. Минимальный результат US1 — один правильный TLS RPC без адресной таблицы, но полное поручение не заканчивается на нём.

Истории разделены наблюдаемым результатом; их технические зависимости не скрываются. US2 использует рабочую регистрацию US1, US3 — её жизненный цикл. Это не разрешает преждевременно объявить US1–US3 выполненными после одного успешного обращения.

## Параллельная работа

Параллельные изменения общих gRPC/SD-файлов не планируются. Пока исполнитель реализует очередную связанную группу, root готовит документацию либо анализирует интеграцию; свежий рецензент проверяет завершённую ревизию отдельно. Для US1/US2/US3 одновременные писатели не нужны, поэтому задач с `[P]` нет.

## Стратегия поставки

Каждый коммит включает минимальный код и подтверждающие проверки одного связанного результата. Отдельный документационный коммит подготовки допустим. Несовместимость отмечается в соответствующих коммитах и PR. Production не меняется. Текущая задача — полный набор согласованных требований, а не только первый успешный RPC.
