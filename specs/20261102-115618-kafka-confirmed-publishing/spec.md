# Подтверждённая публикация событий Kafka

**Ветка**: `infra/kafka/producer-resilience`
**Дата**: 2026-11-02
**Статус**: согласован

## Сценарии и проверки

### US1 — Получить подтверждение отправки (P1)

Приложение ожидает окончательный результат отправки события, чтобы отличать
подтверждённую запись от ошибки или неопределённого исхода.

1. При подтверждённой записи приложение получает topic, partition и offset.
2. Пока отправка не завершилась, результат не возвращается.
3. Ошибка транспорта сохраняется вместе со сведениями о возможной записи.
4. Пустой ответ, неподтверждённый статус или недействительные координаты не считаются успехом.
5. Прекращение ожидания вызывающим кодом не отменяет исходную отправку.

Проверка: настоящий публичный отправитель через регистрацию модуля; управляемый
ответ KafkaFlow для ошибок и реальная Kafka для успешной записи и чтения.
Граница проверок согласована пользователем 2026-11-02.

### US2 — Настроить безопасные повторы (P1)

Приложение может зарегистрировать общую политику и отдельную политику для типа
события через generic-метод, а также явно отключить повторы для типа.

1. Настройка типа или его явное отключение приоритетнее общей политики; политики не складываются.
2. При временном переполнении локальной очереди допустима следующая последовательная попытка.
3. При успехе, исчерпании попыток или небезопасной ошибке возвращается исходный результат или исключение.
4. Широкий пользовательский предикат не разрешает повтор при неизвестном исходе, таймауте, ошибке сериализации, прав, размера или конфигурации.

Проверка: тот же настоящий `IEventProducer`, регистрация модуля и настоящая
Resilience pipeline; подменяется только KafkaFlow-транспорт. Новых внешних границ нет.

## Требования

- **FR-001**: `IEventProducer` предоставляет `Task<DeliveryResult<byte[], byte[]>> ProduceAsync<T>(string key, T message)`.
- **FR-002**: Успех требует `Persisted`, непустого topic, partition >= 0 и offset >= 0.
- **FR-003**: Исключения KafkaFlow передаются без замены; `NotPersisted` сам по себе не доказывает отсутствие записи: Confluent 2.16.0 может пересоздать отчёт ошибки с этим значением по умолчанию. `PossiblyPersisted` допускает запись. Другие ошибки без надёжного отчёта означают неизвестный исход, в том числе ошибки после записи.
- **FR-004**: Отсутствие подтверждённого результата вызывает `InvalidOperationException` и не доказывает недоставку.
- **FR-005**: Без явно зарегистрированной политики один вызов выполняет одну отправку через KafkaFlow; внутренние повторы Kafka сохраняются.
- **FR-006**: Старый `Produce` и маршрутизация/сериализация сохраняют поведение. Пользовательские реализации интерфейса должны реализовать новый метод.
- **FR-007**: Новый метод не принимает токен отмены; `WaitAsync` прекращает только ожидание, исходную задачу можно дождаться отдельно. `MessageTimeout` ограничивает доставку Kafka, но не пользовательские обработчики.

- **FR-008**: Необязательная общая регистрация и generic-регистрация по типу события принимают стандартный `RetryStrategyOptions`; явное отключение типа отменяет общую политику. Без регистрации прежнее поведение.
- **FR-009**: Повтор разрешён только для нефатального `ProduceException<byte[], byte[]>` с `Local_QueueFull`, `NotPersisted` и корректным отчётом для текущего topic. Offset должен быть `Unset`, partition — `Any` либо неотрицательный. Все остальные ошибки и результаты не повторяются, даже при широком `ShouldHandle`.
- **FR-010**: Попытки последовательны и сохраняют исходные ключ, объект события и маршрут. Политика не допускает timeout, hedging или иных стратегий. Число повторов и задержки настраиваются стандартными параметрами; общий бюджет включает внутренние повторы Kafka и задержки политики.
- **FR-011**: Повторная регистрация для той же области заменяет прежнюю; настройка типа приоритетнее общей независимо от порядка регистрации.

## Критерии успеха

- Все успешные результаты содержат действительные координаты подтверждённой записи.
- Небезопасные ошибки остаются доступными вызывающему коду без повторной отправки; исчерпание безопасных повторов сохраняет последнее исходное исключение.
- Прежние проверки публикации проходят без изменения старого метода.

## Границы

`Tasks.Kafka`, конфигурация приложений и OTEL не изменяются.
Нет гарантий обработки потребителем, ровно одного выполнения и сохранения
неотправленных сообщений после перезапуска. Нет нового хранилища. Не гарантируется порядок между параллельными вызовами. Таймауты не повторяются: их статус доставки в Confluent 2.16.0 недостоверен. Произвольные pipeline не подключаются; доступны только стандартные настройки повторов.
