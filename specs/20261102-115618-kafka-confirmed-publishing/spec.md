# Подтверждённая публикация событий Kafka

**Ветка**: `infra/messaging/kafka-produce-async`
**Дата**: 2026-11-02
**Статус**: согласован

## Сценарии и проверки

### US1 — Получить подтверждение отправки (P1)

Приложение ожидает окончательный результат отправки события, чтобы отличать
подтверждённую запись от ошибки или неопределённого исхода.

1. При подтверждённой записи приложение получает topic, partition и offset.
2. Пока отправка не завершилась, результат не возвращается.
3. Ошибка транспорта сохраняется вместе со сведениями о возможной записи.
4. Пустой ответ, неподтверждённый статус или недействительные координаты не считаются успехом.
5. Прекращение ожидания вызывающим кодом не отменяет исходную отправку.

Проверка: настоящий публичный отправитель через регистрацию модуля; управляемый
ответ KafkaFlow для ошибок и реальная Kafka для успешной записи и чтения.
Граница проверок согласована пользователем 2026-11-02.

## Требования

- **FR-001**: `IEventProducer` предоставляет `Task<DeliveryResult<byte[], byte[]>> ProduceAsync<T>(string key, T message)`.
- **FR-002**: Успех требует `Persisted`, непустого topic, partition >= 0 и offset >= 0.
- **FR-003**: Исключения KafkaFlow передаются без замены; `NotPersisted` означает отсутствие записи этой попыткой, `PossiblyPersisted` допускает запись. Другие ошибки без надёжного отчёта означают неизвестный исход, в том числе ошибки после записи.
- **FR-004**: Отсутствие подтверждённого результата вызывает `InvalidOperationException` и не доказывает недоставку.
- **FR-005**: Один вызов выполняет одну отправку через KafkaFlow без дополнительных повторов; внутренние повторы Kafka сохраняются.
- **FR-006**: Старый `Produce` и маршрутизация/сериализация сохраняют поведение. Пользовательские реализации интерфейса должны реализовать новый метод.
- **FR-007**: Новый метод не принимает токен отмены; `WaitAsync` прекращает только ожидание, исходную задачу можно дождаться отдельно. `MessageTimeout` ограничивает доставку Kafka, но не пользовательские обработчики.

## Критерии успеха

- Все успешные результаты содержат действительные координаты подтверждённой записи.
- Все проверенные ошибки остаются доступными вызывающему коду без повторной отправки.
- Прежние проверки публикации проходят без изменения старого метода.

## Границы

`Tasks.Kafka`, конфигурация приложений, версии пакетов и OTEL не изменяются.
Нет гарантий обработки потребителем, ровно одного выполнения и сохранения
неотправленных сообщений после перезапуска. Нет нового хранилища или политики повторов.
