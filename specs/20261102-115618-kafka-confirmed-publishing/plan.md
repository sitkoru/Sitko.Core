# План: подтверждённая публикация Kafka

Ветка: `infra/messaging/kafka-produce-async`. Контракт: [spec.md](spec.md).

## Технический контекст

C#/.NET 10, KafkaFlow 4.2, существующий Confluent.Kafka. xUnit v3/MTP,
существующий Testcontainers.Kafka. Новых пакетов и хранилищ нет.

## Проверка конституции

Причина: void Produce не возвращает окончательный результат доставки.
Переиспользуем KafkaFlow ProduceAsync и DeliveryResult. Одного делегирования
недостаточно: KafkaFlow может вернуть null при прерывании цепочки обработчиков.
Нужна проверка Persisted и координат, иначе возможен ложный успех.
Отдельные типы результата, повторная отправка и общий отправитель для задач не нужны.
Контракт согласован; собственные реализации интерфейса требуют нового метода.

## Структура и порядок

1. src/Sitko.Core.Queue.Kafka/IEventProducer.cs: новый метод, прежний без изменений.
2. tests/Sitko.Core.Queue.Kafka.Tests: через DI проверяем настоящее поведение,
   KafkaFlow подменяем только для контролируемых исходов. Реальная Kafka проверяет
   успешную запись с чтением по полученным координатам. Каждый срез: падающий тест,
   минимальная реализация, успешная проверка.
3. docs/ru/messaging.md и docs/en/messaging.md: использование и ограничения.
4. Анализ диагностик, тесты, независимое ревью при доступности, один связный коммит и PR в v13.

## Ограничения проверки

Сбой реального кластера и производственные настройки не проверяем.
Новые чаты и субагенты запрещены исходным поручением; независимое ревью
не подменяем собственной проверкой и отражаем ограничение при поставке.
